# LAN Power Manager

Custom integration for Home Assistant ([HACS](https://hacs.xyz) compatible) that **scans your local
subnets**, keeps an **inventory of the devices** it finds and **powers computers on (Wake-on-LAN) and
off** (Windows through WMI, or Windows/Linux/macOS through SSH with a key generated by Home Assistant).

In the **LAN Power** sidebar panel you choose which devices to *map*: **only mapped devices become
`switch` entities** (on = the computer answers on the network, `turn_on` = Wake-on-LAN, `turn_off` =
remote shutdown). The rest of the inventory stays in the panel only.

## Features

- **Subnet scan** of the configured networks (CIDR, e.g. `192.168.1.0/24`), on a schedule and on demand
  (panel button or the `lan_power_manager.scan` action). A host is alive if it answers ping or a typical
  port (135, 445, 3389, 22, 80, 443, 139 — a refused connection counts too).
- **Identity from the MAC** (system ARP table, or NetBIOS for Windows PCs): when DHCP changes the IP it
  is still the same device. Name from reverse DNS or NetBIOS, vendor from the MAC prefix.
- **Persistent inventory**: devices that are off stay listed with last IP and last seen. Filters All /
  Mapped / Not mapped / New / Ignored, search, manual add (for computers behind a router, where ARP does
  not reach).
- **Mapping from the panel**: name, IP, MAC, Wake-on-LAN, dedicated broadcast, shutdown method and
  credentials (per device, or the defaults from the options).
- **One switch per mapped device**, with a Home Assistant device linked to the MAC. While turning on/off
  the switch shows the requested state right away (`in_progress` attribute), then checks the computer
  really gets there; the outcome goes to `last_action` / `last_action_ok` and to the
  `lan_power_manager_action_result` event.
- **Power on**: Wake-on-LAN magic packet (ports 9 and 7, repeated) to the device subnet broadcast, to the
  configured broadcast if any, and to `255.255.255.255`.
- **Power off**:
  - **Windows over WMI** (DCOM/RPC, nothing to install on the PC): runs
    `shutdown /s /f /t <delay> /c "<message>"`, so users see the warning and the computer shuts down after
    the delay. Logged-on user rule: *warn, wait and shut down* or *do not shut down* (console user).
  - **SSH** (Windows, Linux, macOS) with the **Home Assistant key**, no password: see
    [Shutdown over SSH](#shutdown-over-ssh). On Windows it runs `shutdown` with delay and message, on
    Linux/macOS `sudo -n shutdown -h now` (customizable).
  - None (power on only).
- Never shuts down the machine Home Assistant runs on.
- `lan_power_manager_new_device` event when a never-seen device appears (not on the first scan), handy
  for notifications.
- Panel and messages in **English and Italian**, following the Home Assistant language.

## Installation

HACS: *HACS → ⋮ → Custom repositories* → URL of this repository, category **Integration** → install
**LAN Power Manager** → restart Home Assistant.

Manual: copy `custom_components/lan_power_manager` to `config/custom_components` and restart.

Then *Settings → Devices & services → Add integration → LAN Power Manager*:

| Field | Notes |
|---|---|
| Subnets | One or more CIDR subnets, comma separated. Pre-filled from the Home Assistant network adapters. Up to /20 each. |
| Username / Password / Domain | Default account for the shutdown (Windows administrator or SSH user). Can be left empty and set per device. |

The integration **Options** also set: full scan interval (0 = manual only, default 60 min), state check
interval of the mapped devices (default 30 s), Windows shutdown delay and message, logged-on user rule.

The **LAN Power** panel appears in the sidebar (administrators only).

## Requirements on the computers

### Wake-on-LAN
- Enabled in BIOS/UEFI and in the network card properties ("Wake on Magic Packet").
- On Windows, turn off *Fast startup*: after a hybrid shutdown some network cards do not wake up.
- For computers on **another subnet** (behind a router) the router must forward *directed broadcasts* to
  that subnet: set the broadcast on the device (e.g. `192.168.20.255`).

### Windows shutdown over WMI
- PC firewall: allow **Windows Management Instrumentation (WMI)** (port 135 + dynamic RPC ports).
- An **administrator** account of the PC (or a domain account). Format `user` + domain, or `DOMAIN\user`.
- With a **local account** (not a domain one) Windows filters remote admin rights: set on the PC
  `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\LocalAccountTokenFilterPolicy = 1` (DWORD).

<a id="shutdown-over-ssh"></a>

### Shutdown over SSH (recommended: no agent, one port, no password)
On first start the integration generates **its own SSH key** (ed25519). The private half stays in the
Home Assistant `.storage` folder; the public half is shown at the top of the panel (*Home Assistant SSH
key*).

For each computer, in the device dialog choose the **SSH** method, the system (Windows or Linux/macOS),
the user, and press **Setup commands**: the panel prepares the commands to paste on the computer.

- **Windows**: paste them in PowerShell run as administrator. They install and start the Windows
  *OpenSSH Server* (a Microsoft component), open port 22 and write the key to
  `C:\ProgramData\ssh\administrators_authorized_keys` with the only permissions Windows accepts
  (Administrators and SYSTEM). For **administrator accounts**.
- **Linux / macOS**: run them as the user Home Assistant logs in with. They add the key to
  `~/.ssh/authorized_keys` and allow passwordless `shutdown` through sudo.

Then **Test connection**: Home Assistant logs in with the key and out again, without running anything.

**Shutdown only.** With this option the key is installed on the computer as
`restrict,command="<shutdown command>"`: whatever the client asks, the computer only runs the shutdown
(no shell, no forwarding). Even if someone copied the key out of Home Assistant, all they could do is shut
the computers down. Command, delay and message are written in the key on the computer: if you change them
in Home Assistant, run the setup commands again.

**Computer identity.** At the first connection Home Assistant stores the computer's host key (its
fingerprint is shown in the dialog). If later the computer presents a different identity, Home Assistant
**does not connect** and says so: if you reinstalled the system or replaced the computer, use *Forget
identity* and test again. The check happens before any credential is sent.

A password is still possible (optional field) but not needed with the key. The logged-on user rule only
applies to the WMI method.

### Home Assistant
- The scan uses ARP/NetBIOS: Home Assistant must be **on the same network** as the computers (HA OS and
  containers with `network_mode: host` are fine). For subnets behind a router, enter the MAC by hand.

## Entities, actions and events

- `switch.<name>`: one entity per mapped device. Attributes: `ip`, `mac`, `hostname`, `online`,
  `in_progress` (`turning_on` / `turning_off`), `shutdown_method`, `last_seen`, `last_action`,
  `last_action_at`, `last_action_ok`.
- Action `lan_power_manager.scan`: immediate scan (returns the counters when called with a response).
- Event `lan_power_manager_new_device`: `device_id`, `ip`, `mac`, `hostname`, `vendor`.
- Event `lan_power_manager_action_result`: `device_id`, `name`, `action` (`on`/`off`), `success`,
  `result` (language-independent outcome code, e.g. `wol_sent`, `turned_off`, `ssh_denied`), `detail`
  (text in the Home Assistant language).

Example — notify new devices:

```yaml
automation:
  - alias: New device on the network
    triggers:
      - trigger: event
        event_type: lan_power_manager_new_device
    actions:
      - action: notify.notify
        data:
          title: New device on the network
          message: "{{ trigger.event.data.hostname or trigger.event.data.ip }} ({{ trigger.event.data.mac }})"
```

## Security

Passwords are stored in the Home Assistant `.storage` folder (like other integrations) and are never sent
to the panel, which only knows whether one is set. The SSH private key never leaves Home Assistant: the
panel only gets the public half. The panel and its websocket commands are for administrators only.

# LAN Power Manager (Italiano)

Integrazione custom (compatibile [HACS](https://hacs.xyz)) che **scansiona le reti locali**, tiene un **inventario dei dispositivi** e
permette di **accendere (Wake-on-LAN) e spegnere i computer**.

Dal pannello web **LAN Power** nella barra laterale scegli quali dispositivi *mappare*: **solo i
dispositivi mappati diventano entità `switch`** in Home Assistant (acceso = il PC risponde in rete;
`turn_on` = Wake-on-LAN, `turn_off` = spegnimento remoto). Tutto il resto dell'inventario resta solo nel
pannello.

## Funzionalità

- **Scansione delle reti** configurate (CIDR, es. `192.168.1.0/24`), automatica a intervalli e manuale
  (pulsante nel pannello o azione `lan_power_manager.scan`). Un host è "vivo" se risponde al ping o su una
  porta tipica (135, 445, 3389, 22, 80, 443, 139 — anche un rifiuto di connessione conta).
- **Identità dal MAC** (tabella ARP del sistema, oppure NetBIOS per i PC Windows): se il DHCP cambia l'IP
  resta lo stesso dispositivo. Nome da DNS inverso o NetBIOS, produttore dal prefisso MAC.
- **Inventario persistente**: i dispositivi spenti restano in elenco con ultimo IP e ultimo contatto. Filtri
  Tutti / Mappati / Non mappati / Nuovi / Ignorati, ricerca, aggiunta manuale (per i PC dietro un router
  dove l'ARP non arriva).
- **Mappatura dal pannello**: nome, IP, MAC, Wake-on-LAN, broadcast dedicato, metodo di spegnimento e
  credenziali (proprie del dispositivo o quelle predefinite delle opzioni).
- **Switch per ogni dispositivo mappato**, con un device HA collegato al MAC. Durante accensione e
  spegnimento lo switch mostra subito lo stato richiesto (attributo `in_progress`) e poi verifica che il
  PC ci arrivi davvero; l'esito finisce in `last_action` / `last_action_ok` e nell'evento
  `lan_power_manager_action_result`.
- **Accensione**: pacchetto Wake-on-LAN (porte 9 e 7, ripetuto) al broadcast della rete del dispositivo,
  al broadcast eventualmente indicato e a `255.255.255.255`.
- **Spegnimento**:
  - **Windows** via WMI (DCOM/RPC, nessun agente da installare): esegue
    `shutdown /s /f /t <preavviso> /c "<messaggio>"`, quindi gli utenti vedono l'avviso a video e il PC si
    spegne dopo il preavviso. Regola per l'utente collegato: *avvisa, aspetta e spegni* oppure *non
    spegnere* (utente alla console).
  - **SSH** (Windows, Linux, macOS) con la **chiave di Home Assistant**, senza password: vedi
    [Spegnimento via SSH](#spegnimento-via-ssh). Su Windows esegue `shutdown` con preavviso e messaggio, su
    Linux/macOS `sudo -n shutdown -h now` (comando personalizzabile).
  - Nessuno (solo accensione).
- Non spegne mai il computer su cui gira Home Assistant.
- Evento `lan_power_manager_new_device` quando compare in rete un dispositivo mai visto (non alla prima
  scansione), utile per le notifiche.

## Installazione

Con HACS: *HACS → ⋮ → Repository personalizzati* → URL di questo repository, categoria **Integrazione** →
installa **LAN Power Manager** → riavvia Home Assistant.

Manuale: copia `custom_components/lan_power_manager` nella cartella `config/custom_components` e riavvia.

Poi *Impostazioni → Dispositivi e servizi → Aggiungi integrazione → LAN Power Manager*:

| Campo | Note |
|---|---|
| Reti | Una o più reti in notazione CIDR separate da virgola. Proposte in automatico dalle schede di rete di HA. Massimo /20 per rete. |
| Utente / Password / Dominio | Account predefinito per lo spegnimento (amministratore Windows o utente SSH). Si possono lasciare vuoti e impostare per singolo dispositivo. |

Dalle **Opzioni** dell'integrazione si cambiano anche: intervallo della scansione completa (0 = solo
manuale, predefinito 60 min), intervallo di controllo dello stato dei dispositivi mappati (predefinito
30 s), preavviso e messaggio di spegnimento Windows, regola per l'utente collegato.

Il pannello **LAN Power** compare nella barra laterale (solo per gli amministratori).

## Requisiti sui computer

### Wake-on-LAN
- Abilitato nel BIOS/UEFI e nelle proprietà della scheda di rete ("Wake on Magic Packet").
- Su Windows conviene disattivare l'*Avvio rapido*, altrimenti da spento "completo" alcuni PC non si
  risvegliano.
- Per i PC in **un'altra rete** (dietro un router) il router deve inoltrare i *directed broadcast* verso
  quella rete: indica nel dispositivo il broadcast (es. `192.168.20.255`).

### Spegnimento Windows (WMI)
- Firewall del PC: consenti **Strumentazione gestione Windows (WMI)** (porta 135 + porte RPC dinamiche).
- Un account **amministratore** del PC (o di dominio). Formato `utente` + dominio, oppure `DOMINIO\utente`.
- Con un **account locale** (non di dominio) Windows filtra i privilegi amministrativi da remoto: imposta
  sul PC
  `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\LocalAccountTokenFilterPolicy = 1` (DWORD).

<a id="spegnimento-via-ssh"></a>

### Spegnimento via SSH (consigliato: nessun agente, una sola porta, niente password)
Al primo avvio l'integrazione genera **una propria chiave SSH** (ed25519). La parte privata resta nella
cartella `.storage` di Home Assistant; la parte pubblica è visibile in cima al pannello (*Chiave SSH di
Home Assistant*).

Per ogni PC, nel dialogo del dispositivo scegli il metodo **SSH**, il sistema (Windows o Linux/macOS),
l'utente, e premi **Comando di installazione**: il pannello prepara i comandi da incollare sul PC.

- **Windows**: incollali in PowerShell aperto come amministratore. Installano e avviano il *Server
  OpenSSH* di Windows (componente Microsoft), aprono la porta 22 e scrivono la chiave in
  `C:\ProgramData\ssh\administrators_authorized_keys` con i soli permessi che Windows accetta
  (Administrators e SYSTEM). Vale per gli **account amministratori**.
- **Linux / macOS**: eseguili con l'utente usato da Home Assistant. Aggiungono la chiave a
  `~/.ssh/authorized_keys` e permettono `shutdown` senza password via sudo.

Poi **Verifica connessione**: Home Assistant entra con la chiave ed esce subito, senza eseguire nulla.

**Solo spegnimento.** Con questa opzione la chiave viene installata sul PC con
`restrict,command="<comando di spegnimento>"`: qualunque cosa chieda chi la usa, il PC esegue solo lo
spegnimento (niente shell, niente inoltri). Anche se qualcuno copiasse la chiave da Home Assistant,
potrebbe solo spegnere i PC. Comando, preavviso e messaggio sono scritti nella chiave sul PC: se li cambi
in Home Assistant, rilancia il comando di installazione.

**Identità del PC.** Alla prima connessione Home Assistant memorizza la chiave di identità del PC (la sua
impronta compare nel dialogo). Se in seguito il PC si presenta con un'altra identità, Home Assistant **non
si collega** e lo segnala: se hai reinstallato il sistema o sostituito il PC usa *Dimentica identità* e
ripeti la verifica. Il controllo avviene prima di inviare qualsiasi credenziale.

Una password resta possibile (campo facoltativo) ma con la chiave non serve. La regola "se c'è un utente
collegato" vale solo per il metodo WMI.

### Home Assistant
- La scansione usa ARP/NetBIOS: Home Assistant deve stare **nella stessa rete** dei PC (HA OS e i container
  con `network_mode: host` vanno bene). Per le reti dietro un router il MAC si inserisce a mano.

## Entità, azioni ed eventi

- `switch.<nome>`: un'entità per dispositivo mappato. Attributi: `ip`, `mac`, `hostname`, `online`,
  `in_progress` (`turning_on` / `turning_off`), `shutdown_method`, `last_seen`, `last_action`,
  `last_action_at`, `last_action_ok`.
- Azione `lan_power_manager.scan`: scansione immediata (restituisce i conteggi se chiamata con risposta).
- Evento `lan_power_manager_new_device`: `device_id`, `ip`, `mac`, `hostname`, `vendor`.
- Evento `lan_power_manager_action_result`: `device_id`, `name`, `action` (`on`/`off`), `success`, `result`
  (codice dell'esito, uguale in tutte le lingue, es. `wol_sent`, `turned_off`, `ssh_denied`), `detail`
  (testo nella lingua di Home Assistant).

Esempio — notifica dei nuovi dispositivi:

```yaml
automation:
  - alias: Nuovo dispositivo in rete
    triggers:
      - trigger: event
        event_type: lan_power_manager_new_device
    actions:
      - action: notify.notify
        data:
          title: Nuovo dispositivo in rete
          message: "{{ trigger.event.data.hostname or trigger.event.data.ip }} ({{ trigger.event.data.mac }})"
```

## Sicurezza

Le password sono salvate nella cartella `.storage` di Home Assistant (come per le altre integrazioni) e
non vengono mai inviate al pannello, che sa solo se una password è impostata. La chiave privata SSH non
lascia mai Home Assistant: al pannello arriva solo la parte pubblica. Pannello e comandi websocket
sono riservati agli amministratori.
