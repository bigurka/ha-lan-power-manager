# LAN Power Manager

Custom integration for Home Assistant ([HACS](https://hacs.xyz) compatible) that **scans your local
subnets**, keeps an **inventory of the devices** it finds and **powers computers on (Wake-on-LAN) and
off** (Windows through WMI, or Windows/Linux/macOS through SSH with a key generated by Home Assistant).

In the **LAN Power** sidebar panel you choose which devices to *map* and which entities each one gets:
**presence** (`device_tracker`), **control** (`switch` + buttons) or **both**. The rest of the inventory
stays in the panel only.

## Features

- **Subnet scan** of the configured networks (CIDR, e.g. `192.168.1.0/24`), on a schedule and on demand
  (panel button or the `lan_power_manager.scan` action). A host is alive if it answers ping or a typical
  port (135, 445, 3389, 22, 80, 443, 139 — a refused connection counts too).
- **Identity from the MAC** (system ARP table, or NetBIOS for Windows PCs): when DHCP changes the IP it
  is still the same device. Name from reverse DNS or NetBIOS, vendor from the full IEEE register of MAC
  prefixes (the same data Home Assistant uses). Phones and other devices with a *random/private* MAC have
  no vendor: that address is not registered to anyone.
- **Persistent inventory**: devices that are off stay listed with last IP and last seen. Filters All /
  Mapped / Not mapped / New / Ignored, search, manual add (for computers behind a router, where ARP does
  not reach).
- **Mapping from the panel**: name, IP, MAC, Wake-on-LAN, dedicated broadcast, shutdown method and
  credentials (per device, or the defaults from the options).
- **Entities per mapped device, your choice**: presence only, control only, or both — see
  [Entities](#entities). A Home Assistant device per mapped device, linked to the MAC.
- While turning on/off the switch shows the requested state right away (`in_progress` attribute), then
  checks the computer really gets there; the outcome goes to `last_action` / `last_action_ok` and to the
  `lan_power_manager_action_result` event.
- **Power on**: Wake-on-LAN magic packet (ports 9 and 7, repeated) to the device subnet broadcast, to the
  configured broadcast if any, and to `255.255.255.255`.
- **Power off**:
  - **Windows over WMI** (DCOM/RPC, nothing to install on the PC): runs
    `shutdown /s /f /t <delay> /c "<message>"`, so users see the warning and the computer shuts down after
    the delay. Logged-on user rule: *warn, wait and shut down* or *do not shut down* (console user).
  - **SSH** (Windows, Linux, macOS) with the **Home Assistant key**, no password: see
    [Shutdown over SSH](#shutdown-over-ssh). On Windows it runs `shutdown` with delay and message, on
    Linux/macOS `sudo -n shutdown -h now` (customizable).
  - None (power on only).
- **Off action per device: shutdown, hibernate or suspend.** It is what turning the switch off does, and
  it shows in the switch name ("Office PC On / Hibernate"). Every action also has its own button — see
  [Off actions](#off-actions).
- Never shuts down the machine Home Assistant runs on.
- `lan_power_manager_new_device` event when a never-seen device appears (not on the first scan), handy
  for notifications.
- Panel and messages in **English and Italian**, following the Home Assistant language.

## Installation

HACS: *HACS → ⋮ → Custom repositories* → URL of this repository, category **Integration** → install
**LAN Power Manager** → restart Home Assistant.

Manual: copy `custom_components/lan_power_manager` to `config/custom_components` and restart.

Then *Settings → Devices & services → Add integration → LAN Power Manager*:

| Field | Notes |
|---|---|
| Subnets | One or more CIDR subnets, comma separated. Pre-filled from the Home Assistant network adapters. Up to /20 each. |
| Username / Password / Domain | Default account for the shutdown (Windows administrator or SSH user). Can be left empty and set per device. |

The integration **Options** also set: full scan interval (0 = manual only, default 60 min), state check
interval of the mapped devices (default 30 s), Windows shutdown delay and message, logged-on user rule.

The **LAN Power** panel appears in the sidebar (administrators only).

## Requirements on the computers

### Wake-on-LAN
- Enabled in BIOS/UEFI and in the network card properties ("Wake on Magic Packet").
- On Windows, turn off *Fast startup*: after a hybrid shutdown some network cards do not wake up.
- For computers on **another subnet** (behind a router) the router must forward *directed broadcasts* to
  that subnet: set the broadcast on the device (e.g. `192.168.20.255`).

### Windows shutdown over WMI
- PC firewall: allow **Windows Management Instrumentation (WMI)** (port 135 + dynamic RPC ports).
- An **administrator** account of the PC (or a domain account). Format `user` + domain, or `DOMAIN\user`.
- With a **local account** (not a domain one) Windows filters remote admin rights: set on the PC
  `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\LocalAccountTokenFilterPolicy = 1` (DWORD).

<a id="shutdown-over-ssh"></a>

### Shutdown over SSH (recommended: no agent, one port, no password)
On first start the integration generates **its own SSH key** (ed25519). The private half stays in the
Home Assistant `.storage` folder; the public half is shown at the top of the panel (*Home Assistant SSH
key*).

First enable the SSH server on the computer: see [Enabling the SSH server](#enabling-the-ssh-server).
Then, for each computer, in the device dialog choose the **SSH** method, the system (Windows, Linux or macOS),
the user, and press **Setup commands**: the panel prepares the commands to paste on the computer.

- **Windows**: paste them in PowerShell run as administrator. They install and start the Windows
  *OpenSSH Server* (a Microsoft component), open port 22 and write the key to
  `C:\ProgramData\ssh\administrators_authorized_keys` with the only permissions Windows accepts
  (Administrators and SYSTEM). For **administrator accounts**.
- **Linux / macOS**: run them as the user Home Assistant logs in with. They add the key to
  `~/.ssh/authorized_keys` and allow passwordless `shutdown` through sudo.

Then **Test connection**: Home Assistant logs in with the key and out again, without running anything.

**This action only.** With this option the key is installed on the computer as
`restrict,command="<command of the off action>"`: whatever the client asks, the computer only runs the
device off action (no shell, no forwarding). Even if someone copied the key out of Home Assistant, all they
could do is shut down / hibernate / suspend the computers. Action, command, delay and message are written in the key on the computer: if you change them
in Home Assistant, run the setup commands again.

**Computer identity.** At the first connection Home Assistant stores the computer's host key (its
fingerprint is shown in the dialog). If later the computer presents a different identity, Home Assistant
**does not connect** and says so: if you reinstalled the system or replaced the computer, use *Forget
identity* and test again. The check happens before any credential is sent.

A password is still possible (optional field) but not needed with the key. The logged-on user rule only
applies to the WMI method.

<a id="enabling-the-ssh-server"></a>

### Enabling the SSH server on the computer
Do this once per computer, then use **Setup commands** in the panel to install the Home Assistant key.

**Windows 10 / 11** (Home and Pro)
1. *Settings → System → Optional features* (Windows 10: *Settings → Apps → Optional features*) →
   *View features* / *Add a feature* → search **OpenSSH Server** → *Install*.
2. Open *Services* (`services.msc`) → **OpenSSH SSH Server** → *Startup type: Automatic* → *Start*.
3. The firewall rule "OpenSSH SSH Server (sshd)" for port 22 is created with the feature. If you use
   another firewall, allow TCP port 22 from Home Assistant.

   Or, in PowerShell run as administrator (the panel's setup commands already do all of this):
   ```powershell
   Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
   Set-Service -Name sshd -StartupType Automatic
   Start-Service sshd
   ```
4. **Which user to enter in Home Assistant** (field *Username* of the device):
   - It must be an account that is an **administrator** of the computer. Check in *Settings → Accounts →
     Your info*: under the name it says "Administrator".
   - Enter the **short Windows user name**, not the e-mail. To find it, open a command prompt on the
     computer and type `whoami`: it answers e.g. `desktop-a1b2\mario`; the user name is the part after
     the backslash, `mario`. It is also the name of the user's folder in `C:\Users\`.
   - If you sign in to Windows with a **Microsoft account** (an e-mail address) this is still the short
     name shown by `whoami` (often the first letters of the e-mail), not the e-mail.
   - Computers in a company **domain**: enter `DOMAIN\user`.
   - Why an administrator: for administrators Windows reads the authorized keys from one shared file,
     `C:\ProgramData\ssh\administrators_authorized_keys`. The panel's setup commands write the key
     there, so it works for every administrator of that computer.

**Linux**
1. Install and start the SSH server:
   - Debian / Ubuntu / Mint / Raspberry Pi OS: `sudo apt install openssh-server` then
     `sudo systemctl enable --now ssh`
   - Fedora / RHEL / Rocky: `sudo dnf install openssh-server` then `sudo systemctl enable --now sshd`
   - Arch: `sudo pacman -S openssh` then `sudo systemctl enable --now sshd`
2. Firewall, if active: `sudo ufw allow ssh` (Ubuntu) or
   `sudo firewall-cmd --permanent --add-service=ssh && sudo firewall-cmd --reload` (Fedora/RHEL).
3. Run the panel's setup commands **as the user Home Assistant logs in with**: they add the key and the
   sudo rule that allows `shutdown` without a password.

**macOS**
1. *System Settings → General → Sharing* → turn on **Remote Login** (older versions: *System Preferences
   → Sharing → Remote Login*). Under "Allow access for" you can limit it to the user Home Assistant uses.
   From Terminal: `sudo systemsetup -setremotelogin on`.
2. Run the panel's setup commands (choose *macOS*) in Terminal as that user.
3. Note: most Macs only wake from **sleep** with Wake-on-LAN (*Wake for network access* in the energy
   settings), not from a full shutdown.

**Check it works**: from another computer `ssh <user>@<ip>` (Windows: `Test-NetConnection <ip> -Port 22`),
then **Test connection** in the panel.

### Home Assistant
- The scan uses ARP/NetBIOS: Home Assistant must be **on the same network** as the computers (HA OS and
  containers with `network_mode: host` are fine). For subnets behind a router, enter the MAC by hand.

<a id="entities"></a>

## Entities

In the device dialog, *Entities in Home Assistant* decides what a mapped device gets:

| Choice | Entities |
|---|---|
| Presence only | `device_tracker.<name>` — `home` when the device answers on the network, `not_home` when not |
| Control only | `switch.<name>` and the buttons |
| Presence and control | all of them |

- `switch.<name>`: on = Wake-on-LAN, off = the device **off action**. The name shows the action
  ("Office PC On / Hibernate", in Italian "Accendi / Iberna"); the entity_id never changes.
- Buttons, only the ones possible for that device:
  `button.<name>_wol` (needs the MAC and Wake-on-LAN enabled), `button.<name>_shutdown`,
  `button.<name>_hibernate` (not on macOS), `button.<name>_suspend` (these three need a shutdown method).
- entity_ids are always in English, names follow the Home Assistant language.
- The device tracker attaches to the Home Assistant device through the MAC; without a MAC it is a
  standalone entity.
- Attributes of the switch: `ip`, `mac`, `hostname`, `online`, `in_progress` (`turning_on` /
  `turning_off`), `shutdown_method`, `off_action`, `last_seen`, `last_action`, `last_action_at`,
  `last_action_ok`.

<a id="off-actions"></a>

## Off actions

Each device has an **off action** (*Off action* in the dialog): what the switch does when turned off.
The buttons run any action, whatever the off action of the switch.

| Action | Button | Windows | Linux | macOS |
|---|---|---|---|---|
| Shutdown | `button.<name>_shutdown` | `shutdown /s /f` with warning and message | `sudo -n shutdown -h now` | `sudo -n shutdown -h now` |
| Hibernate | `button.<name>_hibernate` | `shutdown /h /f` | `sudo -n systemctl hibernate` | not available |
| Suspend | `button.<name>_suspend` | `rundll32 powrprof.dll,SetSuspendState` | `sudo -n systemctl suspend` | `pmset sleepnow` |

- **Windows**: hibernation must be enabled on the computer (`powercfg /h on` in an administrator prompt).
  Suspend uses `SetSuspendState`: if hibernation is enabled, Windows may hibernate instead of sleeping.
  Hibernate and suspend show no warning on screen (Windows does not allow it).
- **Linux**: hibernation needs swap set up for it. The panel's setup commands add the sudo rule for
  `systemctl hibernate` / `suspend` too.
- **macOS** has no hibernate command (it decides by itself with `hibernatemode`).
- **Wake-on-LAN** from hibernation works on many PCs but not all (BIOS / network card); from sleep it
  almost always works. A sleeping computer normally stops answering on the network, so the switch goes off.
- With an SSH key set to **"this action only"**, the computer accepts only the off action of the device:
  the other buttons are refused until you turn that option off (and install the key again).

## Actions and events

- Action `lan_power_manager.scan`: immediate scan (returns the counters when called with a response).
- Event `lan_power_manager_new_device`: `device_id`, `ip`, `mac`, `hostname`, `vendor`.
- Event `lan_power_manager_action_result`: `device_id`, `name`, `action` (`on`/`off`), `success`,
  `result` (language-independent outcome code, e.g. `wol_sent`, `turned_off`, `ssh_denied`), `detail`
  (text in the Home Assistant language).

Example — notify new devices:

```yaml
automation:
  - alias: New device on the network
    triggers:
      - trigger: event
        event_type: lan_power_manager_new_device
    actions:
      - action: notify.notify
        data:
          title: New device on the network
          message: "{{ trigger.event.data.hostname or trigger.event.data.ip }} ({{ trigger.event.data.mac }})"
```

## Security

Passwords are stored in the Home Assistant `.storage` folder (like other integrations) and are never sent
to the panel, which only knows whether one is set. The SSH private key never leaves Home Assistant: the
panel only gets the public half. The panel and its websocket commands are for administrators only.

# LAN Power Manager (Italiano)

Integrazione custom (compatibile [HACS](https://hacs.xyz)) che **scansiona le reti locali**, tiene un **inventario dei dispositivi** e
permette di **accendere (Wake-on-LAN) e spegnere i computer**.

Dal pannello web **LAN Power** nella barra laterale scegli quali dispositivi *mappare* e quali entità
avrà ciascuno: **presenza** (`device_tracker`), **controllo** (`switch` + pulsanti) o **entrambi**. Tutto
il resto dell'inventario resta solo nel pannello.

## Funzionalità

- **Scansione delle reti** configurate (CIDR, es. `192.168.1.0/24`), automatica a intervalli e manuale
  (pulsante nel pannello o azione `lan_power_manager.scan`). Un host è "vivo" se risponde al ping o su una
  porta tipica (135, 445, 3389, 22, 80, 443, 139 — anche un rifiuto di connessione conta).
- **Identità dal MAC** (tabella ARP del sistema, oppure NetBIOS per i PC Windows): se il DHCP cambia l'IP
  resta lo stesso dispositivo. Nome da DNS inverso o NetBIOS, produttore dal registro IEEE completo dei
  prefissi MAC (gli stessi dati usati da Home Assistant). Telefoni e altri dispositivi con MAC
  *casuale/privato* non hanno produttore: quell'indirizzo non è registrato a nessuno.
- **Inventario persistente**: i dispositivi spenti restano in elenco con ultimo IP e ultimo contatto. Filtri
  Tutti / Mappati / Non mappati / Nuovi / Ignorati, ricerca, aggiunta manuale (per i PC dietro un router
  dove l'ARP non arriva).
- **Mappatura dal pannello**: nome, IP, MAC, Wake-on-LAN, broadcast dedicato, metodo di spegnimento e
  credenziali (proprie del dispositivo o quelle predefinite delle opzioni).
- **Entità per dispositivo mappato, a scelta**: solo presenza, solo controllo o entrambi — vedi
  [Entità](#entita). Un dispositivo Home Assistant per ogni dispositivo mappato, collegato al MAC.
- Durante accensione e spegnimento lo switch mostra subito lo stato richiesto (attributo `in_progress`) e
  poi verifica che il PC ci arrivi davvero; l'esito finisce in `last_action` / `last_action_ok` e
  nell'evento `lan_power_manager_action_result`.
- **Accensione**: pacchetto Wake-on-LAN (porte 9 e 7, ripetuto) al broadcast della rete del dispositivo,
  al broadcast eventualmente indicato e a `255.255.255.255`.
- **Spegnimento**:
  - **Windows** via WMI (DCOM/RPC, nessun agente da installare): esegue
    `shutdown /s /f /t <preavviso> /c "<messaggio>"`, quindi gli utenti vedono l'avviso a video e il PC si
    spegne dopo il preavviso. Regola per l'utente collegato: *avvisa, aspetta e spegni* oppure *non
    spegnere* (utente alla console).
  - **SSH** (Windows, Linux, macOS) con la **chiave di Home Assistant**, senza password: vedi
    [Spegnimento via SSH](#spegnimento-via-ssh). Su Windows esegue `shutdown` con preavviso e messaggio, su
    Linux/macOS `sudo -n shutdown -h now` (comando personalizzabile).
  - Nessuno (solo accensione).
- **Azione allo spegnimento per dispositivo: spegni, iberna o sospendi.** È quello che fa lo switch quando
  lo spegni, e compare nel suo nome ("PC Ufficio Accendi / Iberna"). Ogni azione ha anche il suo
  pulsante — vedi [Azioni di spegnimento](#azioni-di-spegnimento).
- Non spegne mai il computer su cui gira Home Assistant.
- Evento `lan_power_manager_new_device` quando compare in rete un dispositivo mai visto (non alla prima
  scansione), utile per le notifiche.

## Installazione

Con HACS: *HACS → ⋮ → Repository personalizzati* → URL di questo repository, categoria **Integrazione** →
installa **LAN Power Manager** → riavvia Home Assistant.

Manuale: copia `custom_components/lan_power_manager` nella cartella `config/custom_components` e riavvia.

Poi *Impostazioni → Dispositivi e servizi → Aggiungi integrazione → LAN Power Manager*:

| Campo | Note |
|---|---|
| Reti | Una o più reti in notazione CIDR separate da virgola. Proposte in automatico dalle schede di rete di HA. Massimo /20 per rete. |
| Utente / Password / Dominio | Account predefinito per lo spegnimento (amministratore Windows o utente SSH). Si possono lasciare vuoti e impostare per singolo dispositivo. |

Dalle **Opzioni** dell'integrazione si cambiano anche: intervallo della scansione completa (0 = solo
manuale, predefinito 60 min), intervallo di controllo dello stato dei dispositivi mappati (predefinito
30 s), preavviso e messaggio di spegnimento Windows, regola per l'utente collegato.

Il pannello **LAN Power** compare nella barra laterale (solo per gli amministratori).

## Requisiti sui computer

### Wake-on-LAN
- Abilitato nel BIOS/UEFI e nelle proprietà della scheda di rete ("Wake on Magic Packet").
- Su Windows conviene disattivare l'*Avvio rapido*, altrimenti da spento "completo" alcuni PC non si
  risvegliano.
- Per i PC in **un'altra rete** (dietro un router) il router deve inoltrare i *directed broadcast* verso
  quella rete: indica nel dispositivo il broadcast (es. `192.168.20.255`).

### Spegnimento Windows (WMI)
- Firewall del PC: consenti **Strumentazione gestione Windows (WMI)** (porta 135 + porte RPC dinamiche).
- Un account **amministratore** del PC (o di dominio). Formato `utente` + dominio, oppure `DOMINIO\utente`.
- Con un **account locale** (non di dominio) Windows filtra i privilegi amministrativi da remoto: imposta
  sul PC
  `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\LocalAccountTokenFilterPolicy = 1` (DWORD).

<a id="spegnimento-via-ssh"></a>

### Spegnimento via SSH (consigliato: nessun agente, una sola porta, niente password)
Al primo avvio l'integrazione genera **una propria chiave SSH** (ed25519). La parte privata resta nella
cartella `.storage` di Home Assistant; la parte pubblica è visibile in cima al pannello (*Chiave SSH di
Home Assistant*).

Prima attiva il server SSH sul computer: vedi [Attivare il server SSH](#attivare-il-server-ssh).
Poi, per ogni PC, nel dialogo del dispositivo scegli il metodo **SSH**, il sistema (Windows, Linux o macOS),
l'utente, e premi **Comando di installazione**: il pannello prepara i comandi da incollare sul PC.

- **Windows**: incollali in PowerShell aperto come amministratore. Installano e avviano il *Server
  OpenSSH* di Windows (componente Microsoft), aprono la porta 22 e scrivono la chiave in
  `C:\ProgramData\ssh\administrators_authorized_keys` con i soli permessi che Windows accetta
  (Administrators e SYSTEM). Vale per gli **account amministratori**.
- **Linux / macOS**: eseguili con l'utente usato da Home Assistant. Aggiungono la chiave a
  `~/.ssh/authorized_keys` e permettono `shutdown` senza password via sudo.

Poi **Verifica connessione**: Home Assistant entra con la chiave ed esce subito, senza eseguire nulla.

**Solo questa azione.** Con questa opzione la chiave viene installata sul PC con
`restrict,command="<comando dell'azione allo spegnimento>"`: qualunque cosa chieda chi la usa, il PC esegue
solo l'azione allo spegnimento del dispositivo (niente shell, niente inoltri). Anche se qualcuno copiasse la
chiave da Home Assistant, potrebbe solo spegnere / ibernare / sospendere i PC. Azione, comando, preavviso e
messaggio sono scritti nella chiave sul PC: se li cambi
in Home Assistant, rilancia il comando di installazione.

**Identità del PC.** Alla prima connessione Home Assistant memorizza la chiave di identità del PC (la sua
impronta compare nel dialogo). Se in seguito il PC si presenta con un'altra identità, Home Assistant **non
si collega** e lo segnala: se hai reinstallato il sistema o sostituito il PC usa *Dimentica identità* e
ripeti la verifica. Il controllo avviene prima di inviare qualsiasi credenziale.

Una password resta possibile (campo facoltativo) ma con la chiave non serve. La regola "se c'è un utente
collegato" vale solo per il metodo WMI.

<a id="attivare-il-server-ssh"></a>

### Attivare il server SSH sul computer
Si fa una volta per computer; poi con **Comando di installazione** nel pannello si installa la chiave di
Home Assistant.

**Windows 10 / 11** (Home e Pro)
1. *Impostazioni → Sistema → Funzionalità facoltative* (Windows 10: *Impostazioni → App → Funzionalità
   facoltative*) → *Visualizza funzionalità* / *Aggiungi una funzionalità* → cerca **Server OpenSSH** →
   *Installa*.
2. Apri *Servizi* (`services.msc`) → **OpenSSH SSH Server** → *Tipo di avvio: Automatico* → *Avvia*.
3. La regola firewall "OpenSSH SSH Server (sshd)" per la porta 22 viene creata con la funzionalità. Se usi
   un altro firewall, consenti la porta TCP 22 da Home Assistant.

   Oppure, in PowerShell aperto come amministratore (il comando di installazione del pannello fa già tutto):
   ```powershell
   Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
   Set-Service -Name sshd -StartupType Automatic
   Start-Service sshd
   ```
4. **Quale utente indicare in Home Assistant** (campo *Utente* del dispositivo):
   - Deve essere un account **amministratore** del computer. Lo verifichi in *Impostazioni → Account →
     Informazioni personali*: sotto il nome c'è scritto "Amministratore".
   - Inserisci il **nome utente breve di Windows**, non l'e-mail. Per trovarlo apri sul computer il
     Prompt dei comandi e scrivi `whoami`: risponde per esempio `desktop-a1b2\mario`; il nome utente è la
     parte dopo la barra, `mario`. È anche il nome della cartella dell'utente in `C:\Users\`.
   - Se entri in Windows con un **account Microsoft** (un indirizzo e-mail) vale lo stesso: si usa il
     nome breve mostrato da `whoami` (spesso le prime lettere dell'e-mail), non l'e-mail.
   - Computer in un **dominio** aziendale: inserisci `DOMINIO\utente`.
   - Perché un amministratore: per gli amministratori Windows legge le chiavi autorizzate da un unico
     file comune, `C:\ProgramData\ssh\administrators_authorized_keys`. Il comando di installazione del
     pannello scrive lì la chiave, quindi vale per tutti gli amministratori di quel computer.

**Linux**
1. Installa e avvia il server SSH:
   - Debian / Ubuntu / Mint / Raspberry Pi OS: `sudo apt install openssh-server` poi
     `sudo systemctl enable --now ssh`
   - Fedora / RHEL / Rocky: `sudo dnf install openssh-server` poi `sudo systemctl enable --now sshd`
   - Arch: `sudo pacman -S openssh` poi `sudo systemctl enable --now sshd`
2. Firewall, se attivo: `sudo ufw allow ssh` (Ubuntu) oppure
   `sudo firewall-cmd --permanent --add-service=ssh && sudo firewall-cmd --reload` (Fedora/RHEL).
3. Esegui il comando di installazione del pannello **con l'utente usato da Home Assistant**: aggiunge la
   chiave e la regola sudo che permette `shutdown` senza password.

**macOS**
1. *Impostazioni di Sistema → Generali → Condivisione* → attiva **Login remoto** (versioni precedenti:
   *Preferenze di Sistema → Condivisione → Login remoto*). In "Consenti l'accesso a" puoi limitarlo
   all'utente usato da Home Assistant. Da Terminale: `sudo systemsetup -setremotelogin on`.
2. Esegui nel Terminale, con quell'utente, il comando di installazione del pannello (scegli *macOS*).
3. Nota: la maggior parte dei Mac si risveglia con il Wake-on-LAN solo dallo **stop** (*Riattiva per
   accesso alla rete* nelle impostazioni di energia), non da spento.

**Verifica**: da un altro computer `ssh <utente>@<ip>` (Windows: `Test-NetConnection <ip> -Port 22`), poi
**Verifica connessione** nel pannello.

### Home Assistant
- La scansione usa ARP/NetBIOS: Home Assistant deve stare **nella stessa rete** dei PC (HA OS e i container
  con `network_mode: host` vanno bene). Per le reti dietro un router il MAC si inserisce a mano.

<a id="entita"></a>

## Entità

Nel dialogo del dispositivo, *Entità in Home Assistant* decide cosa ottiene un dispositivo mappato:

| Scelta | Entità |
|---|---|
| Solo presenza | `device_tracker.<nome>` — `home` quando il dispositivo risponde in rete, `not_home` quando no |
| Solo controllo | `switch.<nome>` e i pulsanti |
| Presenza e controllo | tutte |

- `switch.<nome>`: acceso = Wake-on-LAN, spento = l'**azione allo spegnimento** del dispositivo. Il nome
  mostra l'azione ("PC Ufficio Accendi / Iberna"); l'entity_id non cambia mai.
- Pulsanti, solo quelli possibili per quel dispositivo:
  `button.<nome>_wol` (serve il MAC con il Wake-on-LAN attivo), `button.<nome>_shutdown`,
  `button.<nome>_hibernate` (non su macOS), `button.<nome>_suspend` (questi tre richiedono un metodo di
  spegnimento).
- Gli entity_id sono sempre in inglese, i nomi seguono la lingua di Home Assistant.
- Il device tracker si aggancia al dispositivo Home Assistant tramite il MAC; senza MAC è un'entità a sé.
- Attributi dello switch: `ip`, `mac`, `hostname`, `online`, `in_progress` (`turning_on` /
  `turning_off`), `shutdown_method`, `off_action`, `last_seen`, `last_action`, `last_action_at`,
  `last_action_ok`.

<a id="azioni-di-spegnimento"></a>

## Azioni di spegnimento

Ogni dispositivo ha un'**azione allo spegnimento** (*Azione allo spegnimento* nel dialogo): quello che fa
lo switch quando lo spegni. I pulsanti eseguono qualunque azione, qualunque sia quella dello switch.

| Azione | Pulsante | Windows | Linux | macOS |
|---|---|---|---|---|
| Spegni | `button.<nome>_shutdown` | `shutdown /s /f` con preavviso e messaggio | `sudo -n shutdown -h now` | `sudo -n shutdown -h now` |
| Iberna | `button.<nome>_hibernate` | `shutdown /h /f` | `sudo -n systemctl hibernate` | non disponibile |
| Sospendi | `button.<nome>_suspend` | `rundll32 powrprof.dll,SetSuspendState` | `sudo -n systemctl suspend` | `pmset sleepnow` |

- **Windows**: l'ibernazione va attivata sul PC (`powercfg /h on` nel Prompt dei comandi come
  amministratore). La sospensione usa `SetSuspendState`: se l'ibernazione è attiva, Windows può ibernare al
  posto della sospensione. Ibernazione e sospensione non mostrano avvisi a video (Windows non lo permette).
- **Linux**: l'ibernazione richiede una swap configurata per l'ibernazione. Il comando di installazione del
  pannello aggiunge anche la regola sudo per `systemctl hibernate` / `suspend`.
- **macOS** non ha un comando per ibernare (decide da solo con `hibernatemode`).
- **Wake-on-LAN** dall'ibernazione funziona su molti PC ma non tutti (BIOS / scheda di rete); dalla
  sospensione funziona quasi sempre. Un PC in sospensione di solito smette di rispondere in rete, quindi lo
  switch va su spento.
- Con la chiave SSH impostata su **"solo questa azione"** il PC accetta solo l'azione allo spegnimento del
  dispositivo: gli altri pulsanti vengono rifiutati finché non disattivi l'opzione (e reinstalli la chiave).

## Azioni ed eventi

- Azione `lan_power_manager.scan`: scansione immediata (restituisce i conteggi se chiamata con risposta).
- Evento `lan_power_manager_new_device`: `device_id`, `ip`, `mac`, `hostname`, `vendor`.
- Evento `lan_power_manager_action_result`: `device_id`, `name`, `action` (`on`/`off`), `success`, `result`
  (codice dell'esito, uguale in tutte le lingue, es. `wol_sent`, `turned_off`, `ssh_denied`), `detail`
  (testo nella lingua di Home Assistant).

Esempio — notifica dei nuovi dispositivi:

```yaml
automation:
  - alias: Nuovo dispositivo in rete
    triggers:
      - trigger: event
        event_type: lan_power_manager_new_device
    actions:
      - action: notify.notify
        data:
          title: Nuovo dispositivo in rete
          message: "{{ trigger.event.data.hostname or trigger.event.data.ip }} ({{ trigger.event.data.mac }})"
```

## Sicurezza

Le password sono salvate nella cartella `.storage` di Home Assistant (come per le altre integrazioni) e
non vengono mai inviate al pannello, che sa solo se una password è impostata. La chiave privata SSH non
lascia mai Home Assistant: al pannello arriva solo la parte pubblica. Pannello e comandi websocket
sono riservati agli amministratori.
